# CI and local quality checks — short design

**Intent:** Catch Python formatting, lint, test, lockfile, and package-build regressions on every pull request before the roadmap grows the codebase.

**Current state:** The repository is Python-only, uses uv and has a pytest suite. It has no GitHub Actions workflow. Prettier does not format Python; Ruff covers Python linting and formatting. The user selected the Python 3.12/3.14 matrix with Ruff, tests, and package build on 25 October 2026.

## Approaches

1. A single Python 3.12 job is quick and checks the declared minimum, but misses interpreter compatibility issues on newer Python.
2. A Python 3.12 and 3.14 matrix checks both the package's minimum and a newer runtime, at the cost of a second runner. **Selected by the user.**
3. Add local Git hooks and more security/type-checking tools at the same time. This adds setup and maintenance before those checks have been chosen; revisit when contributors or dependency security needs justify them.

## Chosen behavior

On pull requests targeting `main`, pushes to `main`, and manual dispatch, GitHub Actions runs a locked `uv` environment on Python 3.12 and 3.14. Each matrix job runs Ruff lint, Ruff formatting check, the full pytest suite, and builds wheel plus source distribution. Ruff uses a small explicit rule set and a locked version so rule changes arrive by deliberate dependency updates.

README documents the same checks for local use. Actions are pinned to immutable commit SHAs with release comments, permissions are read-only, and the workflow uses only repository contents. Prettier, type checking, security scanners, local hooks, and GitHub branch protection settings are outside this change. Workflow checks report on the existing PR; requiring them for merge remains a repository setting.

The later quality gates are sequenced in the [quality and CI roadmap](../../quality-roadmap.md).
