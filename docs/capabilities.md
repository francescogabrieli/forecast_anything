# Capability matrix

This matrix describes the code in the release-candidate checkout. It is not a claim of production readiness, a published service, or general forecasting-quality acceptance. The [roadmap](roadmap.md) includes future work; the [quickstart](quickstart.md) identifies supported installation paths.

| Area | Implemented | Boundary or pending acceptance |
| --- | --- | --- |
| Source connectors | Explicitly mapped local CSV and bounded HTTP JSON GET | No generic database, spreadsheet, arbitrary API, pagination or streaming connector. HTTP secrets require an injected resolver. |
| Source interpretation | Sanitized sample of at most 100 rows, field types, proposed roles, unresolved semantics | Suggestions do not become executable mappings automatically. Availability time, identity, revision, unit, cadence, timezone, Gregorian calendar and missing sentinels must be explicit. |
| Temporal snapshots | Availability-aware freeze, revision handling, immutable snapshot identity | No inference of original publication dates; declared availability assumptions remain assumptions. |
| Future Graph | Typed acyclic graph validation, explicit provider/operator registries and representation negotiation | No implicit resampling, calendar alignment, unit conversion or stochastic coupling. |
| Baseline comparator | Product reference only; explicit library fixtures also support seasonal repetition with explicit positive period; point results on fixed UTC hourly/daily grids | Rejects missing history and known-future inputs; no imputation, quantiles, joint paths or calibrated probabilities. |
| Timestral engine | Required pinned local model for primary product forecasts; point and marginal-quantile output | Normal installation includes pinned code; explicit `model prepare` provisions/verifies weights. No Mistral API key or silent fallback; metadata reads do not load Torch. Real CPU fp32 parity and one owner-authorized local benchmark passed; weight license remains applicable to each user's own deployment. No joint paths. |

## Demonstrations and evidence

The current minimal CLI example uses synthetic observations and pinned local Timestral. It requires prepared weights. Earlier baseline CLI evidence and deterministic library fixtures remain historical examples of execution and persistence.

The MCP subprocess fixture uses the official SDK reference client and a real API plus an independent worker. An accepted forecast completes after MCP disconnects; the original key returns the same job/run after reconnection. Later observed outcomes refresh the original registered source and yield persisted single-run metrics. The configured/backtest journey compares a period-2 alternating series with a period-1 comparator: manual MAE 0 versus 1, two selected origins in each frozen partition, with one early insufficient-history exclusion. It terminates the worker after partial persistence, corrupts the CSV, restarts API/worker, and verifies unchanged archive/plan, child identities, paginated origins and report. A second process fixture retains missing-target and unavailable-history exclusions. An installed-wheel test repeats both baseline and configured/backtest recovery journeys outside the checkout with locked dependencies and the optional extra. See [acceptance evidence and remaining gates](research/forecast-evidence.md). These are fixed-clock synthetic tests, without an LLM, desktop assistant host or general predictive-quality claim.

MCP source profiling is mutating: the existing core route may enqueue durable template discovery, whose worker persists snapshots, epochs, candidates and graphs and may schedule optional agent discovery. Profiling has no caller-key replay guarantee. Profile/refresh of explicitly operator-allowed stored HTTP sources may cause core network access; both advertise an open world. The two new submission tools also advertise mutation and an open world: backtests capture an operator-allowed CSV source, while configured forecasts reuse a stored CSV or HTTP snapshot without source I/O; selected numerical providers may use configured external resources. Completed summary/origin reads are immutable and do not enqueue work. An unpublished report returns `not_found`; inspect pending/failed state through `get_job`. Backtesting initially supports one series/unit on fixed UTC hourly/daily grids and preserves only revisions supplied at capture, with explicit exclusions and insufficient evidence. These tests establish no predictive-quality claim. Generic backtest evaluations have no discovery attestation and cannot qualify or activate watches; candidate-bound Timestral backtests qualify only their frozen candidate with fresh final windows. MCP exposes no arbitrary network request tool, HTTP registration tool or private archive/plan reader.

The browser E2E fixture starts the real API and a worker with a fixed clock, synthetic CSV sources and seasonal-naive provider. Two journeys cover source activation, explicit first forecast and refresh, two-source evaluation, revision notification, graph keyboard interaction, a disrupted/reconnected event stream and an immutable scenario comparison. Its fixed local token is test-only. It neither measures model quality nor validates a paid provider. The five-person usability study is on hold; these automated journeys do not establish external usability acceptance.

The agent tests use scripted responses. The Docker restart check interrupts a real Eve turn after a budgeted core operation and resumes the same session; the isolated fixture simulates expiry of Graphile Worker's four-hour stale-job lock. A separate bounded live GPT-6 Luna smoke sent one 3,132-byte request (maximum 128 output tokens), received a function call for `inspect_source` (518 input and 23 output tokens), and confirmed its persisted operation ID in the local core. It used only synthetic data and does not evaluate model quality or production readiness.

The real Timestral parity, installed-model and browser checks are explicitly guarded; a separate genuine-model acceptance was executed. An owner-authorized CPU fp32 parity run and local cross-domain benchmark were completed separately; a skipped routine test, adapter unit test or dependency install does not reproduce those results. See [Timestral status](implementation/timestral.md), [the pinned benchmark evidence](research/timestral-benchmark/report.json), [agent decisions](decisions/agent-runtime.md), [operator semantics](implementation/operators.md) and [API contracts](implementation/api.md) for the detailed boundaries.

## Extension contracts

`ForecastProvider` declares `capabilities() -> Capabilities` and `forecast(request: ForecastRequest) -> ForecastResult`. Runtime registration is explicit. The result identifies the actual provider/revision and carries its available numerical representations and assumptions.

`Operator` declares `contract() -> OperatorContract` and `apply(inputs: dict[str, NodeValue], config: dict) -> ForecastResult`. Representation negotiation describes guarantees, not a representation that an input might happen to return. Paths must preserve the same sampled-world identity across inputs.

`SourceSpec` identifies a `csv` or `http_json` source, private location, optional private `secret_ref`, explicit mapping and positive refresh interval. See the [connector guide](connectors.md); adding a source kind requires a deliberate contract change rather than a parallel example-only format.

## Required-model acceptance

| Boundary | Required provider check |
| --- | --- |
| CLI | The production runtime loads pinned Timestral and validates the primary forecast ancestry. Inference distinguishes `model_not_prepared`, `missing_model_dependency`, `model_code_revision_mismatch` and `model_load_failed`. See `model status` and `model prepare`. |
| API and MCP | Authenticated capabilities describe the required provider and inspected model status. Forecast/backtest requests go through the same core policy; the adapter delegates computation. |
| Discovery and watch | Product epochs and candidate graphs include the required model context. Incompatible historical watches are paused with an explicit reason. |
| Backtest and worker | Plans pin the model and comparator separately. The worker rechecks compatibility before work and preserves prior evidence. |
