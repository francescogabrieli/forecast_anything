# Optional discovery agent

This package is the isolated Eve adapter for the core discovery job. The Python core and deterministic forecasting paths do not depend on this service. It exposes only the authenticated `POST /forecast/discover` and `GET /forecast/discover/:sessionId` bridge to the worker. The standard Eve session API denies callers; the default home route is disabled.

## Runtime and compatibility

- Node 26.0.0 and npm 11.12.1 were used for this evaluation.
- Eve is pinned at `0.83.0`. The Postgres Workflow World is pinned at `5.0.5`; its dependency on `@workflow/world@5.0.5` exactly matches Eve's resolved `@workflow/world@5.0.5`. The bundled Eve docs still mention an older beta line; the installed package metadata and lockfile are the compatibility evidence.
- Eve supports self hosting, direct AI SDK providers, and `@workflow/world-postgres` for durable sessions. This package uses the OpenAI Responses API for orchestration, configured with `OPENAI_MODEL_ID` (default `gpt-6-luna`) and `OPENAI_API_KEY`. Provide the key only to the Eve service environment; OpenAI API billing is separate from a ChatGPT subscription. Mistral is reserved for Timestral forecasting in the Python provider. Tests and builds make no provider calls.
- `FORECAST_AGENT_DATABASE_URL` (or `WORKFLOW_POSTGRES_URL`) stores bridge session metadata in `forecast_agent.discovery_sessions`, separate from the Workflow World tables. Configure the Workflow World Postgres connection according to its package documentation. The restart check uses an ephemeral local Postgres container.
- `FORECAST_AGENT_BRIDGE_TOKEN` authenticates the Python worker to the two bridge routes. `FORECAST_AGENT_CORE_URL` and the distinct `FORECAST_AGENT_CORE_TOKEN` authenticate tools to **only** `/v1/agent/operations`. A remote core URL must use HTTPS; HTTP is accepted only for `localhost`, `127.0.0.1`, or `[::1]`. Never give the agent the workspace token or source credentials.

`POST` parks a deterministic `discovery/<job_id>` Eve session and persists its session ID. The Python worker checkpoints the ID before its first `GET`. Polling sends the first turn with a stable Eve idempotency key. Every actual tool call sends Eve's `callId` to the core, which reserves the persistent A2 budget and issues the operation ID before executing. Model prose is ignored; only core validated tool results become candidates. `expected_deviation`, `forecast_change`, and `declared_limit` are the executable registry. Unknown template ideas can be saved as **non-executable** candidates only.

The tool allowlist contains `inspect_source`, `propose_candidates`, and `explain_run`. `defaultTools: false` excludes optional shell, file, and web tools. No MCP connections, skills, or subagents are installed. The Docker sandbox uses `deny-all` networking. Authored core operations use an application fetch wrapper that accepts only the configured core origin; the direct OpenAI SDK uses its custom fetch hook with the fixed `https://api.openai.com` origin. Both reject other HTTP(S) origins and redirects.

Apply [`compose.agent-egress.yaml`](compose.agent-egress.yaml) after the deployment's base Compose file. Its `!override` network declaration removes any default/outbound networks from the Eve service and attaches it only to an internal network with no direct outbound route; only the hardened proxy also joins the outbound network, and that proxy permits TLS CONNECT to `api.openai.com:443` alone. Node 24.5+ routes its fetch calls through that proxy. Attach the self-hosted core and Workflow Postgres services to `agent_internal` so they remain reachable without external routing. Do not attach the Eve service to `agent_outbound` or publish the proxy port. The Docker sandbox remains `deny-all`; its network policy is separate from the Eve service's egress policy. The overlay does not support a managed Postgres endpoint outside the internal network without a separately reviewed and tested allowlist extension.

## Checks

Run `npm ci --ignore-scripts`, `npm audit --omit=dev --audit-level=high`, `npm run contracts:check`, `npm run typecheck`, `npm test -- --run`, `npm run build`, `bash scripts/check-egress-policy.sh`, and `bash scripts/check-postgres-restart.sh`. The Docker checks need a running daemon. The egress check confirms direct Internet sockets, Mistral chat, and unlisted HTTPS origins are blocked while the OpenAI HTTPS origin is reachable. The restart check bootstraps disposable Postgres and a synthetic Python core, pauses after a real budgeted `inspectSource` operation, restarts Eve and Postgres, and verifies recovery in the same session, reuse of the persisted operation ID, one candidate proposal, and unchanged budget. The fixture ages the isolated Graphile Worker lock past its four-hour stale-lock expiry; it does not wait four hours.

Historical note: an earlier synthetic end-to-end check used `ministral-3b-latest` to call `inspect_source` against a local synthetic core job. It predates and does not validate the selected OpenAI orchestration provider. On 2026-10-26, after explicit approval, a bounded GPT-6 Luna smoke made one 3,132-byte request with a 128-token output cap, called `inspect_source` (518 input and 23 output tokens), and confirmed the operation ID persisted in the local core through an Eve session. The synthetic check validates the basic provider-to-core tool path only; it does not establish model quality or production readiness. No GPT live call is part of automated checks. No production source data or Timestral weights were used.
